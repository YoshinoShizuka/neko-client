# Neko Client（虚空仓库客户端增强）

纯客户端 Fabric mod，给「虚空仓库」的界面（一个 6 行原版大箱子）加这几件事：

1. **搜索框** —— 支持**中文 / 拼音全拼 / 拼音首字母 / 注册名**筛选物品。服务端 GUI 一个字节不变，纯原版玩家零感知。
2. **取满手势** —— 按住组合键 + 点一格，取出到背包放不下为止。常规模式给**纯散货**，潜影盒模式给**满盒**；装多少由服务端按你的真实背包现算。
3. **配方本浏览、搜索与删除**（0.4.8 起，0.5.0 重做界面）—— 按热键打开，每行有**物品图标** +
   「产物 × 产出数 ← 原料 ×数量」；一整本**连续滚动**（滚到底自动续拉，不再翻页；
   一次显示多少条按屏幕高度现算），
   顶部搜索框支持**中文 / 拼音 / 首字母 / 模糊拼音 / 注册名**，**匹配得最准的置顶**。逐条删除（点两次确认）。
   一份本子全服共用，删一条对所有人生效。
4. **独立开关 + 可自定义热键** —— 两个功能各一套，由 **malilib**（MiniHUD / Litematica 那套）管，设置落 `config/neko-client.json`。
5. **聊天静音开关**（0.5.2）—— 打开后，本客户端不再显示虚空仓库发来的**任何**聊天提示（含配方本那些不带前缀的续行）。只管显示，服务端照常发、别人照常看。
6. **仓库补货**（0.5.3）—— 投影容器填充缺料时自动从虚空仓库取货；不再提供独立热键选项。
7. **投影容器填充**（0.5.4，批次 A）—— 装了 Litematica 时，右键投影里的箱子/漏斗/发射器等容器，打开后按投影内容**逐格填充**；缺料自动接仓库补货，补不齐会在聊天里报出**还缺多少**（0.5.5）；仓库多给的填充物在填完后自动退回仓库（同一轮）。默认关闭，与 quickcraft 共存时各读各的开关。
8. **容器填充物合计**（0.5.6）—— 一张表：整张原理图**所有容器里要求的物品**加起来，对照**背包 + 虚空仓库**看还缺多少。不需要开着容器、也不需要正在填充。入口是 **Litematica 材料列表工具栏上的「容器材料」按钮**（0.5.7），另有一个默认未绑定的热键。

## 工作方式

```
打开仓库界面 ──search_hello──▶ 服务端确认是虚空仓库
             ◀─search_catalog─ 仓库物品 id 目录（≈30 KB）
输入 ─▶ 本地匹配（中文名 / 全拼 / 首字母 / 注册名，jpinyin 建索引）
     ──search_apply──▶ 服务端按 Item 身份过滤出页（空列表 = 恢复完整列表）
```

匹配在客户端做（只有客户端有中文语言文件），服务端只做集合求交。过滤是**会话级**状态：关掉界面即消失，不写存档；页码回第一页。服务端限流 hello 100ms / apply 50ms，目录上限 4096 种。

## 取满手势

```
按住组合键 + 绑定的鼠标键点仓库格 ──fill_request{slotId}──▶ 服务端
                                                      ├─ 校验：菜单必须是虚空仓库
                                                      ├─ 校验：slotId 必须是内容格
                                                      ├─ 校验：这一格要解析得出物品
                                                      ├─ 限流 50ms
                                                      └─ fill()：常规 = 纯散货 / 盒模式 = 满盒
◀──────────────────── 聊天提示「已取出 N 个 <物品>」─────────────────────
```

- **组合键**：`keyFillCombo`，**默认 `LEFT_CONTROL,LEFT_ALT,BUTTON_2`（Ctrl + Alt + 右键）**；**清空 = 关掉手势**。三种写法都支持：
  - **鼠标键 + 修饰键**（默认形态）：一个鼠标键（`BUTTON_1` 左 / `BUTTON_2` 右 / `BUTTON_3` 中，26.3 也可写 `MOUSE_LEFT` / `MOUSE_RIGHT` / `MOUSE_MIDDLE`）+ 任意几个 Shift / Ctrl / Alt；
  - **键盘键 + 鼠标键**：例如 `R,BUTTON_1` —— 按着 `R` 点左键才算；
  - **只有键盘键（单个按键）**：例如只绑 `R`，或只绑 `LEFT_ALT` —— 按着它点**任意**鼠标键都算。0.5.7 及以前这种绑定会被判成「没有鼠标键」而**一次都不生效**，是这一轮修掉的。
- **判据严格匹配**：**绑了**鼠标键就必须逐位相等，没有任何容错 —— 绑右键时 `Ctrl+Alt+左键` 一定不触发，反之亦然。没绑鼠标键时才有「点哪个键都算」，那是形态本身，不是放宽。
- **键盘键怎么知道按着没有**：客户端不轮询键盘状态（26.x 的 `InputConstants.isKeyDown` 把 SDLK 当 scancode 索引，恒 false —— 见下），而是把 `KeyboardHandler#keyPress` 的按下 / 松开记进一张小账本（`FillKeyState`），点击时对账。松开事件丢了（按住键切窗口）时，关掉界面即整份清空。
- **只认前 5 行内容格**：第 6 行是导航行，玩家背包 / 快捷栏都不是取满目标。点错区域时日志会写出具体区域名。
- **只发 `slotId`**：物品是什么、能装多少，全由服务端从自己的数据和你的真实背包现算，客户端报的数字一概不作数。
- 客户端**只有真的把包发出去**才 cancel 原版点击；对端是老服务端（没这条通道）时原样放行，退回「取 1 个」。
- 「能装多少」= 三个上限取最小：背包放得下多少 / 仓库里有多少 / 盒模式下材料够做几盒。**一个都装不下时**会发提示，不会静默失败。

> 🔴 **不生效怎么查**：进服后日志会打印 `取满组合键=…（判定：可用 / 不可用：原因 / 需按住 R 再点格子）`，之后每次带修饰键的点击、以及绑了键盘键之后的每次点击，都会留一行判据日志（点的是哪个键码、绑的是哪个、**当前按着哪些键**、命不命中），点错区域会写出「区域=玩家背包 / 快捷栏 / 第 6 行导航行」。绑了键盘键却「一次按键都没记到」时会直接写出「按键跟踪没挂上」。完整排障表、五轮真机事故与日志证据见本地排障手册 `docs/取满手势五轮事故与排障手册.md`（该文件按项目铁律只留在本地，不随仓库分发）。

## 投影容器填充（0.5.4，批次 A）

```
安装 Litematica + 打开 projectionFill
  → 右键投影中的容器（箱子 / 木桶 / 漏斗 / 发射器 / 熔炉 …）
  → 打开真实容器后，客户端按投影 NBT 逐槽位点击填充
  → 缺的物品自动从虚空仓库取到背包，取到后续填；关箱即可
```

- **默认关闭**：这是新功能，不能让升级后的老玩家突然发现右键变了。`projectionFill` 关着时相关 tick 监听器直接空转。
- **Litematica 是可选依赖**：没装时读不到投影，右键行为原样；26.1.1 借用 26.1.2 的 Litematica 编译，不会因缺类崩溃。
- **1.21.11 的降级**：右键自动填充可用；1.21.11 没有对应的界面压制注入点，故不硬挂那三份 mixin（跨容器连续填充入口已移除，不再依赖该差异）。
- **与 quickcraft 共存**：两个 mod 同时安装时各读各的开关，本模组**不再自动让位**；日志只提示可能双份响应右键，由玩家自己取舍。
- **缺料自动补货**：模板缺的物品会通过 `printer_take` 逐种从虚空仓库取到背包（需要 carpet-Neko-Addition 1.0.17+ 且 `voidWarehouseRestock` 开启）；回执确认背包真的变多后才续填，服务端不支持时按原样报缺料；补不齐时聊天会说清差多少（见下节）。
- **一次右键填到底**（同一轮修掉）：补料是异步的（发包 → 等回执 → 再填）。此前自动填充在发出请求后立刻关掉容器，回执回来已经没有菜单可填 —— 真机表现是「第一次右键只把一组材料取到快捷栏，容器一点没填；要再右键一次才填」。现在容器会留到补料链收尾，续填完再替你关掉。
- **范围**：批次 A 只搬填充主路径；容器锁、材料自动收集、Quick Shulker 桥接、3D 预览和验证器 UI 都用 stub 顶住，后续批次再补。

## 补货比对：容器里要多少 vs 仓库里给到多少（0.5.5）

```
模板第 3 格要 64 个铁锭 ──printer_take──▶ 仓库能给多少给多少
                        ◀──服务端回 OK + 背包真的多了 N 个──
N = 64 → 静默续填；N < 64 → 聊天报「还缺 64−N」
```

- 🔴 **比的是容器里的填充物，不是投影的方块总数**：需求逐格来自投影容器的 NBT（「这一格要 64 个铁锭」）。schematic 的方块统计说的是「这座建筑用了多少方块」，跟「这个箱子该装什么」是两回事 —— 拿它当需求会算出完全对不上的缺口。
- **到手件数只认背包增量**：`printer_take` 的回执只有状态、没有件数，所以判据是「服务端回 `OK`」∩「背包里这件东西真的变多了多少」。非 `OK` 一律记 0 —— 背包数字有变化属于别的原因（别人的货 / 迟到回执 / 你自己手动拿的）。
- **有缺口才说话**：补齐了就静默续填；一件都没给报「仓库里没有 X ×N」，只给一部分报「X 仓库只补到 M，还缺 K」。需求未知的条目（`need = 0`）不参与报缺口，免得报出假的「缺 0」。
- **不动协议**：全在客户端算，`printer_take` 一个字节没改，老服务端照常工作。

## 余料自动返还（同一轮）

投影填充从仓库取的是「这种物品能给多少给多少」，而容器往往只用其中一小部分。填完之后，剩下的会走 `printer_return` 整格退回仓库：

```
仓库给 64、容器只要 20 ──printer_take──▶ 背包 64
   └─ 填充用掉 20 ──▶ 背包剩 44 ──printer_return{槽位号}──▶ 仓库
```

- **退多少**：账本先记「仓库这一轮到手多少件」，再在填充**真的重填那一轮**扣掉「这一轮会用掉多少」= `min(到手, 缺口)`；最后再用「现在手里比开始要货前多了多少」夹一次，取小。三道夹子都不在时（容器被提前关掉、填充没重填）账上就是整批货 —— 那批货会原样回仓库，不会烂在背包里。
- **退哪几格**：只有账本**完整覆盖整格**才上交，差 1 个都跳过 —— 服务端按整格收，放行一次就等于把玩家自己的存货退走。潜影盒、带数据组件的同种物品整格跳过；**玩家选中的那一格不跳过**（服务端 `PrinterTakeService#tryGive` 从 slot 0 起找空位，货几乎总落在快捷栏第一格，而那一格默认就是选中格 —— 跳过它等于最大那堆余料永远退不掉）。
- **什么时候退**：补料链停下 2 秒、且没有容器界面开着才发一批。连续填充在几十个容器之间连轴转时账一路累加，整片填完才退一次，不会「退 → 要 → 退」空转。
- **通道**：与 carpet-Neko-Addition 1.0.17 的 `printer_return` / `printer_return_result` 逐字节同构；对面不支持就静默放弃。printer 同时在场时可能抢走回执接收器，这时用背包差分兜底（那几格真的空了就算成功）。
- **看得见**：动作栏打「余料已退回仓库：X ×N、…」；日志 `[虚空仓库退料]` 记下基线、账上件数与每批槽位号。

## 容器填充物合计（0.5.6）

```
打开某张图的材料列表 ──▶ 点工具栏「容器材料」──▶ 只算这一张图的投影
   （或按热键）                                  ──▶ 读每个容器方块的 NBT（Items 列表）
                                                 ──▶ 按物品累加
                                                 ──▶ 打开 Litematica 自己的材料列表界面
                                                     需要 = 容器里写的数量
                                                     已有 = 背包 + 虚空仓库（只读查询）
                                                     缺失 = 需要 − 已有
```

- 🔴 **数的是容器里该装什么，不是方块**：Litematica 自带的材料列表数「这座建筑用了 320 个箱子」，回答不了「这些箱子该装什么」。这张表逐格读投影容器 NBT 里写的 `Items`，按物品加到一张表上。
- **入口在材料列表工具栏上**（0.5.7）：随便打开一个投影的材料列表（F6 → 材料列表），工具栏最右一个按钮「导出到文件」右边会多一个 **「容器材料」**。点它就进合计表。不需要开着容器、不需要正在填充、不需要 `projectionFill`；没有投影时打开就是一张空表 —— 那本身就是答案。热键（默认未绑定）仍然可用，效果一样。
- 🔴 **算的是哪一张图，跟着入口走**：从蜂箱农场的材料列表点按钮，算的就是蜂箱农场；从「加载原理图」里点，算的就是那份原理图文件。两条入口给的类不同 —— 投影列表给 `MaterialListPlacement`（持有 `SchematicPlacement`），加载原理图 / 原理图管理器给 `MaterialListSchematic`（持有 `LitematicaSchematic`，**跟有没有放置无关**）—— 两者都把这层关系放在 private 字段里、**没有 getter**，所以按**字段类型**反射取。🔴 扫描单元是「一张图」而不是「一个投影」：没放置的图照样算得出容器材料。拿不到对应关系（热键从世界里直接打开）才退回「所有启用的投影」，标题那时会写「等 N 个」。
- 🔴 **按钮位置是量出来的，不是写死的**：工具栏按钮数量和宽度随语言和列表类型变（中文 7 个、支持渲染层时 8 个、窗口太窄还会折行），所以按钮贴在「该行最右一个按钮的右边缘 + 4」。用的是 malilib 的 `ButtonGeneric`，和工具栏其余按钮同款。
- **装不装 Litematica 都不影响别的功能**：这个按钮在单独一份 `neko_client_litematica.mixins.json`（`required: false`）里 —— 没装 Litematica 时整份配置静默跳过。
- **标题带原理图名字**（0.5.7）：写成 `原理图'蜂箱农场'容器材料`，和 Litematica 自己的「原理图'X'材料列表」同一个读法。只有退回「全部启用」时才是「第一个 + 等 N 个」；一个投影都没有时明确写「没有启用的投影」。
- **「已有」包含虚空仓库**：仓库那一半走只读查询（`printer_query`，与 `litematica-printer` 同一条通道）。装了 printer 时**不抢接收器**，直接读它同步好的缓存；没装才自己注册。**不扣库存、不动背包**。
- 🔴 **装了 printer 时必须把自己登记成「当前材料列表」**：它的查询是照着 `DataManager.getMaterialList()` 里那张表去问的，而 Litematica 只在「还没有当前材料列表」时才登记新表。玩家先看过原版材料列表之后，printer 会一直按**那张表**问库存 —— 本表里不在那张表的物品全显示 0（真机踩过：两边「白色染色玻璃」都是 998941，而箭 / 紫颂花 / 铁桶 / 骨头 全 0，因为它们不是方块材料）。所以本界面打开时接管 `DataManager`，关闭时原样还回去。
- 🔴 **「缺失」列要按渲染者分开给值**：printer 给行的渲染加了 Redirect，它以为 `missing` 和 `available` 是两个独立的量（原版语义），会再减一次已有。所以装了 printer 时我们给 `需求`，让它减完正好是「需求 − 已有」；没装时直接给「需求 − 已有」。给错了会变成 `需求 − 2 × 已有`，仓库只补到一半的行会少报一半缺口。表头合计不受影响（它按「需求 − 已有」现算）。
- **数字会自己刷新，而且不卡**：仓库回执到了之后只重算「已有 / 缺失」，不重扫投影（需求跟仓库无关）。🔴 渲染热路径（每帧、每行）**只查两张内存表**：仓库快照由后台整份替换，背包计数每 0.5 秒整份重算 —— 旧实现是在这里逐行扫 36 格背包 + 逐行反射读 printer 缓存（几百行 × 60 帧 = 每秒几万次），这正是「已有数量比对很慢」的根因。表头那行合计只在数字真变了时才重建（它等于整个界面重排），且被节流挡下的那一次**不会吞掉**这次变化。没人看这个界面时，库存轮询与缓存读取全部停下。
- 🔴 **首屏为什么以前要等 5 秒**（这一轮修掉）：装了 printer 时数字来自它的缓存，而它**每 5 秒才问服务端一次**，且没有「立即刷新」的公开入口 —— 打开本界面后最坏要 5 秒 + 一次往返 + 我们的搬运间隔，才看到第一眼数字。现在界面刚打开时会把它的 5 秒闸归零、直接调一次它自己的 `tick()`（只推这一下，之后仍按它的节奏走：抢节奏会让服务端回 `THROTTLED`，而它收到非 OK 会把缓存整份清空 ⇒ 数字先闪成 0）；自有查询通道那条路则免掉「首屏还要等 2 秒间隔」。搬运间隔 0.5 秒 → 0.25 秒。日志会打一行 `已有数量首次到达：N 条，开屏后 K tick`，快不快看它。
- **范围**：默认只有**当前材料列表那一张图**（拿不到对应关系时退回「所有启用的投影」）；同一物品散在多个容器里是相加。潜影盒按「一个盒子」算，不展开里面的 27 组 —— 那与填充行为不符。
- **不做双箱配对 / 实体容器**：原版双箱只有一个方块实体带 `Items`，逐条加不会重复；驴羊驼身上的箱子不是方块，投影里没有可靠快照，先不算。

## 安装

mod id `neko_client`，构件名 `neko-client`，五个 Minecraft 版本各一个 jar：

| 客户端版本 | jar | 构建管线 |
| --- | --- | --- |
| 26.3 / 26.2 / 26.1.2 / 26.1.1 | `neko-client-mc<ver>-0.5.7.jar` | fabric-loom（非 remap，Java 25） |
| 1.21.11 | `neko-client-mc1.21.11-0.5.7.jar` | fabric-loom-remap + officialMojangMappings（Java 21） |

| 位置 | 需要什么 |
| --- | --- |
| 客户端 | 本 mod（按版本选 jar）+ **malilib**（同版本，硬依赖）+ Fabric API |
| 服务端 | `carpet-Neko-Addition` 1.0.16+（对应版本 jar；本 mod 不是它的硬依赖，没有它时搜索框自动隐藏） |
| 纯原版客户端 | 什么都不用装，看不到任何变化 |

> 🔴 **0.3.0 起需要 malilib**（masa 系模组的公共库，装过 MiniHUD / Litematica / Tweakeroo 的玩家已经有）。原版按键绑定只在没有界面时派发，而这两个键恰恰都是在仓库界面里按的 —— 换 malilib 才能让热键在界面打开时也响应，顺带得到一个和 MiniHUD 同款的配置界面。

## 使用

- 打开虚空仓库界面，点击界面上方的搜索框；输入 `铁锭` / `tieding` / `td` / `iron_ingot` 均可命中，清空 = 恢复完整列表。
- **按住组合键（默认 Ctrl + Alt）+ 绑定的鼠标键（默认右键）**点仓库**前 5 行**的物品格，取出到背包放不下为止。想用左键就到「快捷键」页改，或把 `keyFillCombo` 写成 `LEFT_CONTROL,LEFT_ALT,BUTTON_1`。只想要一个键也行（`R` / `LEFT_ALT` 单键 + 点任意鼠标键），见上面「取满手势」一节。
- 🔴 聚焦搜索框时**所有按键都会被吞掉**（ESC = 退出搜索框，再按一次关界面）—— 否则数字键 `1-9` 会触发原版「把快捷栏整组存进仓库」的 SWAP 语义。

### 开关与热键

| 配置项 | 默认 | 关掉之后 |
| --- | --- | --- |
| `searchBox` | `true` | 界面里**不再创建**搜索框（不占地方、不吃按键、不发 `search_apply`），取满手势照常可用 |
| `fillGesture` | `true` | 取满手势退回原版「取 1 个」，搜索框照常可用（组合键还绑着也不响应） |
| `silenceChat`（0.5.2） | `false` | 打开后隐藏虚空仓库的全部聊天提示（见下节）；关掉后新消息立刻恢复 |
| `projectionFill`（0.5.4） | `false` | 打开后右键投影容器会按投影内容填充；关闭时右键行为完全原样 |

| 热键（配置界面里的名字） | 默认键 | 说明 |
| --- | --- | --- |
| 搜索框 / `searchBox` | **未绑定** | 切搜索框；界面开着时立刻生效 |
| 取满手势 / `fillGesture` | **未绑定** | 切取满手势；立刻生效 |
| 静音聊天 / `silenceChat` | **未绑定** | 切聊天静音；立刻生效 |
| 取满组合键 / `fillCombo` | `LEFT_CONTROL,LEFT_ALT,BUTTON_2` | **不是开关，是手势本身**：按住它再点格子。绑了鼠标键就只认那一个；只绑键盘键（`R`）时点任意鼠标键 |
| 打开配置界面 / `openGui` | **未绑定** | 打开本模组的 malilib 配置界面 |
| 打开配方本 / `openRecipes` | **未绑定** | 打开配方本浏览界面（0.4.8 新增；0.5.0 起带图标/滚动/搜索；随地可用，不必开着仓库） |
| 容器填充物合计 / `openContainerMaterials` | **未绑定** | 打开整张原理图的容器填充物合计表（0.5.6）：需要 / 已有（背包 + 虚空仓库）/ 缺失三列，随地可用。0.5.7 起主入口是材料列表工具栏的「容器材料」按钮，这条热键是备用的 |

各开关热键默认留空，是因为 `H` / `J` / `V` 这种单字母键在整合包里几乎必然与别的模组撞车。`fillCombo` 是唯一给默认值的例外 —— 它是**手势本身**，留空等于把「可配置化」做成功能删除。

### 聊天静音（0.5.2）

`silenceChat` 打开后，客户端在收到**系统聊天包**的那一刻丢掉虚空仓库的提示，判据是三条文本特征：中文 `[虚空仓库] `、英文 `[Void Warehouse] `、以及配方本续行开头 `└ `（这一种**不带前缀**，所以单独匹配）。三种都只认**开头**，玩家在普通聊天里引用一句虚空仓库的话不会被误杀。

- 只影响**你看不看得见**：服务端照常发、别人照常看到、已经留在聊天栏里的历史消息也不会被清掉。
- 不需要开仓库界面、不需要服务端配合；单独打开这个开关也不会发起任何握手。
- 判据是纯文本类，单测直接覆盖三种前缀与「句中引用不许命中」的负向样本；落点在 `handleSystemChat` 的 HEAD，命中即取消。

- **怎么绑**：从 **Mod Menu** 或任意 malilib 模组的配置界面右上角下拉框里选「Neko Client」，点热键按钮 → 按下新键（鼠标键也能绑：先点按钮进入「> … <」态，再按住修饰键点鼠标键；ESC 取消、Delete 清空）。
- **配置界面分了页**（与 MiniHUD 同款）：**全部** / **通用**（两个功能开关 + 聊天静音）/ **快捷键**（取满组合键、打开配置界面）。`fillCombo` 放「快捷键」页，因为它是个纯热键、不是布尔开关。
- **配置文件**：`config/neko-client.json`（首次启动自动生成，带 `_readme` 注释；空串 = 未绑定）。
- **生效时机**：界面里改 / 按热键 → 立刻 + 当场写回；手改 json → **退出重进一次世界**。
- ⚠️ 两个开关**都关**时打开界面，界面里不会创建搜索框；此时用热键打开搜索框，需要关掉界面再开一次（框是在界面初始化时建的）。

### 配方本（0.4.8 起；0.5.0 重做界面）

按「打开配方本」热键（默认未绑定，在配置界面「快捷键」页设）打开：

```
已用 137 / 2048 · 已显示 32 / 137 条
[🔍 搜索产物名 / 物品 id                                ]
[🗡] 铁剑 ×1   原料：铁锭 ×2、木棍 ×1         [删除]
[⛏] 铁镐 ×1   原料：铁锭 ×3、木棍 ×2         [删除]
[排序：按名字] [清空搜索] [重试]             [关闭]
```

- **图标 + 连续滚动**（0.5.0）：产物图标在文字左侧，产出数标在图标角上（同背包数字）。
  一次要 32 条（服务端上限）；**预取裕量按屏幕现算**（0.5.1：可见行数 = 列表内容区高度 ÷ 行高，
  内容区 = 列表高 − 搜索框等固定开销 31px；裕量 = max(4, 可见行数 / 2)）——
  大屏提前拉得多，小屏省流量，滚到底不会「停下等包」。
  报「已显示 32 / 137 条」，页码不再进界面。
- **列表高度贴合屏幕**（0.5.1 布局修复）：以前写死「屏幕高 − 100」，底部按钮行上方固定空
  30px、加上行数取整余数最多空约 50px；现在按「整行数」从按钮行向上反推列表高度，
  最后一行始终贴住按钮行上方 4px，不再有大片空白。
- **搜索**（0.5.0；0.5.1 加模糊拼音）：顶部输入本地化名、拼音、首字母或 id
  （`铁剑` / `tiesi` / `ts` / `iron` 都行），250 ms 防抖后把命中的**产物 id 白名单**发服务端重查，
  按匹配度置顶：**名字完全相等 > 前缀 > 包含 > 拼音 > 只命中 id**。
  **模糊拼音**：翘舌归平舌（zh/ch/sh→z/c/s）、前后鼻音归一（ing/ang/eng→in/an/en）、
  n/l/r 归一组、f/h 归一组 —— 打 `niuhuang` 也能搜到硫磺（liuhuang），`zurou` 能搜到猪肉（zhurou）。
  只搜产物不搜原料；搜到 0 个时客户端直接拦住（服务端把空名单当「不过滤」，发出去会拉回整本）。
- **删除要点两次**：第一次变「确认删除？」，3 秒内再点才真发。全服共用、**没有撤销**；
  删完同一 tick 就不可合成，合成成功一次又会记回来（`recipeId` 由内容算出）。
- **排序**：点「排序：按名字」在两种顺序间切换，「按名字」= 产物 id 字典序（稳定，续拉不重复/漏条）、
  「最近学习」= 刚学会的在前（每次点击都从当前状态翻转，按钮文字即时更新，列表回到顶部从头重取）。搜索态以匹配度为准。
- **打开就有内容**：索引与明细是两个包，自动要第一页；丢了会补要两次（仍空才写「没能取到这一页」）。
- 🔴 **不需要开着仓库界面**：随地按热键就能看（服务端 1.0.17 起只看 `voidWarehouse` + `voidWarehouseCraft`）。
  打不开只有两种说法：服务端不回 = 提示版本/规则 + 「重试」；对端没通道 = 只闪一句动作栏提示。
- 服务端需要 `carpet-Neko-Addition` **1.0.17+**（1.0.16 能浏览，但搜索入口会落到「没回应」）。

## 构建

JDK 25、Gradle 9.7.0（wrapper 已固定）。多子工程：`common/`（纯逻辑 SearchIndex + 单测）+ `modern/`（26.x 四版本）+ `versions/1.21.11`。

```bat
.\gradlew.bat :modern:26.3:test        REM 26.3 共 173 条（余料返还 28 条：夹子 5 + 扫描/挑格 6 + 销账 5 + 回执取数 3 + 场景回放 9）
.\gradlew.bat :common:test             REM SearchIndex 11 条
.\gradlew.bat :modern:26.3:build dist
.\gradlew.bat :versions:1.21.11:dist
```

- 🔴 **逐版本构建**（与 carpet 同款铁律）：全量 `build` 在 26.x 与 1.21.11 混跑时可能撞 TinyRemapper。
- 🔴 **与服务端 jar 成对更新**：`neko/voidwarehouse/search/` 三个 payload 类 + `neko/voidwarehouse/fill/FillRequestPayload` + `neko/voidwarehouse/restock/` 六个通道类（`printer_take*`、`printer_query*`、`printer_return*`）与 carpet-Neko-Addition 里同名类**必须逐字节一致**（同 FQCN 双份、Fabric 只加载一份）。改一边务必同步改另一边，校验口径见排障手册。
- malilib 依赖坐标在各自 `gradle.properties`（`malilib_version` + `malilib_artifact`），仓库走 `https://masa.dy.fi/maven/sakura-ryoko`；26.x 用 `implementation`，**1.21.11 必须 `modImplementation`**（那份 jar 是中间名，不 remap 一行都编译不过）。
- 交付前必跑 **184 条单测（26.3 173 + common 11）+ 2611 条** jar 级字节码断言 + 变异（模板在工作区 `.workbuddy/tools/`），细节见排障手册。

## 版本差异（仅两处）

| 差异点 | 26.x | 1.21.11 |
| --- | --- | --- |
| 网络注册 | `serverboundPlay()` / `clientboundPlay()` | `playC2S()` / `playS2C()` |
| 渲染注入 | `extractRenderState(GuiGraphicsExtractor,...)` | `render(GuiGraphics,int,int,float)` |

两代容器屏都不渲染 renderables，搜索框都必须手动驱动。其余源码五版本逐字节相同（换行统一 CRLF）。0.5.2 的聊天静音 mixin 也是五版本同一份源码；`handleSystemChat` / `content()` 在 1.21.11 的产物里被 remap 成中间名（`method_43596` / `comp_763`），断言按版本分支咬。
