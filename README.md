# Neko Client（虚空仓库客户端增强）

纯客户端 Fabric mod，给「虚空仓库」的界面（一个 6 行原版大箱子）加四件事：

1. **搜索框** —— 支持**中文 / 拼音全拼 / 拼音首字母 / 注册名**筛选物品。服务端 GUI 一个字节不变，纯原版玩家零感知。
2. **取满手势** —— 按住组合键 + 点一格，取出到背包放不下为止。常规模式给**纯散货**，潜影盒模式给**满盒**；装多少由服务端按你的真实背包现算。
3. **配方本浏览、搜索与删除**（0.4.8 起，0.5.0 重做界面）—— 按热键打开，每行有**物品图标** +
   「产物 × 产出数 ← 原料 ×数量」；一整本**连续滚动**（滚到底自动续拉，不再翻页；
   一次显示多少条按屏幕高度现算），
   顶部搜索框支持**中文 / 拼音 / 首字母 / 模糊拼音 / 注册名**，**匹配得最准的置顶**。逐条删除（点两次确认）。
   一份本子全服共用，删一条对所有人生效。
4. **独立开关 + 可自定义热键** —— 两个功能各一套，由 **malilib**（MiniHUD / Litematica 那套）管，设置落 `config/neko-client.json`。

## 工作方式

```
打开仓库界面 ──search_hello──▶ 服务端确认是虚空仓库
             ◀─search_catalog─ 仓库物品 id 目录（≈30 KB）
输入 ─▶ 本地匹配（中文名 / 全拼 / 首字母 / 注册名，jpinyin 建索引）
     ──search_apply──▶ 服务端按 Item 身份过滤出页（空列表 = 恢复完整列表）
```

匹配在客户端做（只有客户端有中文语言文件），服务端只做集合求交。过滤是**会话级**状态：关掉界面即消失，不写存档；页码回第一页。服务端限流 hello 100ms / apply 50ms，目录上限 4096 种。

## 取满手势

```
按住组合键 + 绑定的鼠标键点仓库格 ──fill_request{slotId}──▶ 服务端
                                                      ├─ 校验：菜单必须是虚空仓库
                                                      ├─ 校验：slotId 必须是内容格
                                                      ├─ 校验：这一格要解析得出物品
                                                      ├─ 限流 50ms
                                                      └─ fill()：常规 = 纯散货 / 盒模式 = 满盒
◀──────────────────── 聊天提示「已取出 N 个 <物品>」─────────────────────
```

- **组合键**：`keyFillCombo`，**默认 `LEFT_CONTROL,LEFT_ALT,BUTTON_2`（Ctrl + Alt + 右键）**。绑定里必须恰好一个鼠标键（`BUTTON_1` 左 / `BUTTON_2` 右 / `BUTTON_3` 中，26.3 也可写 `MOUSE_LEFT` / `MOUSE_RIGHT` / `MOUSE_MIDDLE`）+ 任意几个 Shift / Ctrl / Alt；**清空 = 关掉手势**。
- **判据严格匹配**：点的鼠标键码必须与绑定的逐位相等，没有任何容错 —— 绑右键时 `Ctrl+Alt+左键` 一定不触发，反之亦然。
- **只认前 5 行内容格**：第 6 行是导航行，玩家背包 / 快捷栏都不是取满目标。点错区域时日志会写出具体区域名。
- **只发 `slotId`**：物品是什么、能装多少，全由服务端从自己的数据和你的真实背包现算，客户端报的数字一概不作数。
- 客户端**只有真的把包发出去**才 cancel 原版点击；对端是老服务端（没这条通道）时原样放行，退回「取 1 个」。
- 「能装多少」= 三个上限取最小：背包放得下多少 / 仓库里有多少 / 盒模式下材料够做几盒。**一个都装不下时**会发提示，不会静默失败。

> 🔴 **不生效怎么查**：进服后日志会打印 `取满组合键=…（判定：可用 / 不可用：原因）`，之后每次带修饰键的点击都会留一行判据日志（点的是哪个键码、绑的是哪个、命不命中），点错区域会写出「区域=玩家背包 / 快捷栏 / 第 6 行导航行」。完整排障表、五轮真机事故与日志证据见 [`docs/取满手势五轮事故与排障手册.md`](docs/取满手势五轮事故与排障手册.md)。

## 安装

mod id `neko_client`，构件名 `neko-client`，五个 Minecraft 版本各一个 jar：

| 客户端版本 | jar | 构建管线 |
| --- | --- | --- |
| 26.3 / 26.2 / 26.1.2 / 26.1.1 | `neko-client-mc<ver>-0.5.1.jar` | fabric-loom（非 remap，Java 25） |
| 1.21.11 | `neko-client-mc1.21.11-0.5.1.jar` | fabric-loom-remap + officialMojangMappings（Java 21） |

| 位置 | 需要什么 |
| --- | --- |
| 客户端 | 本 mod（按版本选 jar）+ **malilib**（同版本，硬依赖）+ Fabric API |
| 服务端 | `carpet-Neko-Addition` 1.0.16+（对应版本 jar；本 mod 不是它的硬依赖，没有它时搜索框自动隐藏） |
| 纯原版客户端 | 什么都不用装，看不到任何变化 |

> 🔴 **0.3.0 起需要 malilib**（masa 系模组的公共库，装过 MiniHUD / Litematica / Tweakeroo 的玩家已经有）。原版按键绑定只在没有界面时派发，而这两个键恰恰都是在仓库界面里按的 —— 换 malilib 才能让热键在界面打开时也响应，顺带得到一个和 MiniHUD 同款的配置界面。

## 使用

- 打开虚空仓库界面，点击界面上方的搜索框；输入 `铁锭` / `tieding` / `td` / `iron_ingot` 均可命中，清空 = 恢复完整列表。
- **按住组合键（默认 Ctrl + Alt）+ 绑定的鼠标键（默认右键）**点仓库**前 5 行**的物品格，取出到背包放不下为止。想用左键就到「快捷键」页改，或把 `keyFillCombo` 写成 `LEFT_CONTROL,LEFT_ALT,BUTTON_1`。
- 🔴 聚焦搜索框时**所有按键都会被吞掉**（ESC = 退出搜索框，再按一次关界面）—— 否则数字键 `1-9` 会触发原版「把快捷栏整组存进仓库」的 SWAP 语义。

### 开关与热键

| 配置项 | 默认 | 关掉之后 |
| --- | --- | --- |
| `searchBox` | `true` | 界面里**不再创建**搜索框（不占地方、不吃按键、不发 `search_apply`），取满手势照常可用 |
| `fillGesture` | `true` | 取满手势退回原版「取 1 个」，搜索框照常可用（组合键还绑着也不响应） |

| 热键（配置界面里的名字） | 默认键 | 说明 |
| --- | --- | --- |
| 搜索框 / `searchBox` | **未绑定** | 切搜索框；界面开着时立刻生效 |
| 取满手势 / `fillGesture` | **未绑定** | 切取满手势；立刻生效 |
| 取满组合键 / `fillCombo` | `LEFT_CONTROL,LEFT_ALT,BUTTON_2` | **不是开关，是手势本身**：按住它再点格子。只认绑定的那个鼠标键，未绑定的键一律不触发 |
| 打开配置界面 / `openGui` | **未绑定** | 打开本模组的 malilib 配置界面 |
| 打开配方本 / `openRecipes` | **未绑定** | 打开配方本浏览界面（0.4.8 新增；0.5.0 起带图标/滚动/搜索；随地可用，不必开着仓库） |

三条开关热键默认留空，是因为 `H` / `J` / `V` 这种单字母键在整合包里几乎必然与别的模组撞车。`fillCombo` 是唯一给默认值的例外 —— 它是**手势本身**，留空等于把「可配置化」做成功能删除。

- **怎么绑**：从 **Mod Menu** 或任意 malilib 模组的配置界面右上角下拉框里选「Neko Client」，点热键按钮 → 按下新键（鼠标键也能绑：先点按钮进入「> … <」态，再按住修饰键点鼠标键；ESC 取消、Delete 清空）。
- **配置界面分了页**（与 MiniHUD 同款）：**全部** / **通用**（两个功能开关）/ **快捷键**（取满组合键、打开配置界面）。`fillCombo` 放「快捷键」页，因为它是个纯热键、不是布尔开关。
- **配置文件**：`config/neko-client.json`（首次启动自动生成，带 `_readme` 注释；空串 = 未绑定）。
- **生效时机**：界面里改 / 按热键 → 立刻 + 当场写回；手改 json → **退出重进一次世界**。
- ⚠️ 两个开关**都关**时打开界面，界面里不会创建搜索框；此时用热键打开搜索框，需要关掉界面再开一次（框是在界面初始化时建的）。

### 配方本（0.4.8 起；0.5.0 重做界面）

按「打开配方本」热键（默认未绑定，在配置界面「快捷键」页设）打开：

```
已用 137 / 2048 · 已显示 32 / 137 条
[🔍 搜索产物名 / 物品 id                                ]
[🗡] 铁剑 ×1   原料：铁锭 ×2、木棍 ×1         [删除]
[⛏] 铁镐 ×1   原料：铁锭 ×3、木棍 ×2         [删除]
[排序：按名字] [清空搜索] [重试]             [关闭]
```

- **图标 + 连续滚动**（0.5.0）：产物图标在文字左侧，产出数标在图标角上（同背包数字）。
  一次要 32 条（服务端上限）；**预取裕量按屏幕现算**（0.5.1：可见行数 = 列表内容区高度 ÷ 行高，
  内容区 = 列表高 − 搜索框等固定开销 31px；裕量 = max(4, 可见行数 / 2)）——
  大屏提前拉得多，小屏省流量，滚到底不会「停下等包」。
  报「已显示 32 / 137 条」，页码不再进界面。
- **列表高度贴合屏幕**（0.5.1 布局修复）：以前写死「屏幕高 − 100」，底部按钮行上方固定空
  30px、加上行数取整余数最多空约 50px；现在按「整行数」从按钮行向上反推列表高度，
  最后一行始终贴住按钮行上方 4px，不再有大片空白。
- **搜索**（0.5.0；0.5.1 加模糊拼音）：顶部输入本地化名、拼音、首字母或 id
  （`铁剑` / `tiesi` / `ts` / `iron` 都行），250 ms 防抖后把命中的**产物 id 白名单**发服务端重查，
  按匹配度置顶：**名字完全相等 > 前缀 > 包含 > 拼音 > 只命中 id**。
  **模糊拼音**：翘舌归平舌（zh/ch/sh→z/c/s）、前后鼻音归一（ing/ang/eng→in/an/en）、
  n/l/r 归一组、f/h 归一组 —— 打 `niuhuang` 也能搜到硫磺（liuhuang），`zurou` 能搜到猪肉（zhurou）。
  只搜产物不搜原料；搜到 0 个时客户端直接拦住（服务端把空名单当「不过滤」，发出去会拉回整本）。
- **删除要点两次**：第一次变「确认删除？」，3 秒内再点才真发。全服共用、**没有撤销**；
  删完同一 tick 就不可合成，合成成功一次又会记回来（`recipeId` 由内容算出）。
- **排序**：「按名字」= 产物 id 字典序（稳定，续拉不重复/漏条）；「最近学习」= 刚学的在前。搜索态以匹配度为准。
- **打开就有内容**：索引与明细是两个包，自动要第一页；丢了会补要两次（仍空才写「没能取到这一页」）。
- 🔴 **不需要开着仓库界面**：随地按热键就能看（服务端 1.0.17 起只看 `voidWarehouse` + `voidWarehouseCraft`）。
  打不开只有两种说法：服务端不回 = 提示版本/规则 + 「重试」；对端没通道 = 只闪一句动作栏提示。
- 服务端需要 `carpet-Neko-Addition` **1.0.17+**（1.0.16 能浏览，但搜索入口会落到「没回应」）。

## 构建

JDK 25、Gradle 9.7.0（wrapper 已固定）。多子工程：`common/`（纯逻辑 SearchIndex + 单测）+ `modern/`（26.x 四版本）+ `versions/1.21.11`。

```bat
.\gradlew.bat :modern:26.3:test        REM 配置 20 + 组合键 18 + 配方本 43（含拼音/模糊拼音 6 + 动态裕量 1）= 81 条
.\gradlew.bat :common:test             REM SearchIndex 11 条
.\gradlew.bat :modern:26.3:build dist
.\gradlew.bat :versions:1.21.11:dist
```

- 🔴 **逐版本构建**（与 carpet 同款铁律）：全量 `build` 在 26.x 与 1.21.11 混跑时可能撞 TinyRemapper。
- 🔴 **与服务端 jar 成对更新**：`neko/voidwarehouse/search/` 三个 payload 类 + `neko/voidwarehouse/fill/FillRequestPayload` 与 carpet-Neko-Addition 里同名类**必须逐字节一致**（同 FQCN 双份、Fabric 只加载一份）。改一边务必同步改另一边，校验口径见排障手册。
- malilib 依赖坐标在各自 `gradle.properties`（`malilib_version` + `malilib_artifact`），仓库走 `https://masa.dy.fi/maven/sakura-ryoko`；26.x 用 `implementation`，**1.21.11 必须 `modImplementation`**（那份 jar 是中间名，不 remap 一行都编译不过）。
- 交付前必跑 **1193 条** jar 级字节码断言 + 变异（模板在工作区 `.workbuddy/tools/`），细节见排障手册。

## 版本差异（仅两处）

| 差异点 | 26.x | 1.21.11 |
| --- | --- | --- |
| 网络注册 | `serverboundPlay()` / `clientboundPlay()` | `playC2S()` / `playS2C()` |
| 渲染注入 | `extractRenderState(GuiGraphicsExtractor,...)` | `render(GuiGraphics,int,int,float)` |

两代容器屏都不渲染 renderables，搜索框都必须手动驱动。其余源码五版本逐字节相同（换行统一 CRLF）。

## 版本兼容

| 服务端 \ 客户端 | 装了本 mod | 没装 / 老版本 |
| --- | --- | --- |
| carpet-Neko-Addition 1.0.16+（对应版本） | 搜索框可用 | 无任何影响 |
| 其它版本 / 没装 carpet | 搜索框自动隐藏（`canSend` 判定） | 无任何影响 |
| 客户端没装 malilib | **模组不会加载**（硬依赖，Fabric 直接弹缺依赖） | — |
