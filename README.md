# Neko Client（虚空仓库客户端增强）

纯客户端 Fabric mod，给「虚空仓库」的界面（一个 6 行原版大箱子）加两件事：

1. **搜索框**：支持**中文 / 拼音全拼 / 拼音首字母 / 注册名**搜索筛选物品。服务端 GUI 一个字节不变，纯原版玩家零感知。
2. **取满手势：按住组合键 + 点一格 → 把这一格的物品取出到背包放不下为止**（0.2.0 新增；0.4.3 起组合键由玩家自定义，0.4.6 起绑什么鼠标键就只有那个键生效，默认仍是 Ctrl + Alt + 左键）。常规模式给**纯散货**（一个盒子都不装），潜影盒模式给**满盒**，都是「能装多少装多少」——装多少由服务端按你的真实背包现算，只取仓库里现有的（不走 9 合 1 兑换）。
3. **两个功能各有独立开关 + 可自定义热键**（0.2.0 起）。开关与热键都由 **malilib** 管（就是 MiniHUD / Litematica 那套）：一行一个「复选框 + 按键按钮」。**开关热键默认全部留空（未绑定）**，自己到配置界面里绑一个。设置落 `config/neko-client.json`。

> 🔴 **取满手势连续三轮真机事故，0.4.6 才真正做到「绑什么键就是什么键」**。
> - **0.4.3**：把组合键做成配置项 `keyFillCombo`，却用 malilib 的 `KeybindMulti.isKeyDown`
>   去查「某个键按着没有」。26.x 的 malilib 把 **SDLK**（`LEFT_CONTROL` = 1073742048）当成
>   SDL 的 **scancode**（0..511）去索引键盘状态缓冲区，读到缓冲区外一兆字节处的内存，
>   恰好是 0 ⇒ 恒 false、不抛异常、日志零报错。
> - **0.4.4**：改问**点击事件自带的修饰键掩码**（原版 Shift 快速移动读的就是它）。
>   但真机复测仍然「按了没反应」：日志里唯一一条判据快照抓到的是
>   `按钮=3 → 键码=-97 绑定鼠标键=-99 … 命中=false`，而且那条日志**只打一次**，
>   之后真正的点击一个字都没留下。
> - **0.4.5**：① 槽位改成**按点击坐标现算**（原版 `isHovering` 四周各 1px 的宽容框），不再读渲染帧写的
>   `hoveredSlot` 字段；② `warehouse` 目录标志从「动作通道的硬门禁」降级成视图标志——服务端
>   `FillNetwork#handleFill` 本来就自己验 `voidWarehouse` 规则 + `VoidWarehouseMenu`；
>   ③ 整条链路的静默 return 都换成带原因的日志；④ **但加了一条错误的「按钮号容错 ±2」**：
>   绑了修饰键时键码差 ≤2 就算命中。真机确实开始 `已取出 …` 了，日志连续十几次写着
>   `按钮=3 → -97 … 命中（按钮号容错 ±2）` —— 玩家绑的是 Ctrl+Alt+**左键**，真正生效的大面积是
>   **右键**，反馈原话「实际生效的不是 Ctrl+Alt+左键 而是 Ctrl+Alt+右键」。**功能能用 ≠ 语义正确**。
> - **0.4.6**：撤销全部隐性容错，判据只剩一条严格匹配（`绑定键码 == 原版按钮号 - 100`）；
>   日志对「按钮号对不上」直接写出点的是哪个码、绑的是哪个码；判据日志与链路结果日志
>   **分级、各用一份限流预算**（0.4.5 曾把 `取满发包成功` 挤出日志）。
>
> ⚠️ **代价**：组合键仍是「**恰好一个鼠标键 + 任意几个 Shift / Ctrl / Alt**」。原版只对外暴露这三位
> 修饰键的实时状态，字母 / 数字键绑了会被判「组合键不可用」并在日志写清原因 —— 绝不再静默失效。
> **0.4.6 起绑什么键就是什么键**：默认 `BUTTON_1`（左键）时右键 / 中键 / 侧键一律不触发。
> 想用右键就把鼠标键显式改成 `BUTTON_2`（26.3 也可写 `MOUSE_RIGHT`），中键是 `BUTTON_3`。
> 想改成 `Shift + 左键`、`Alt + 右键` 都行；**清空 = 关掉手势**。
> 🔴 配置里存的是**键名**不是码值，由各版本 malilib 自己解析：26.3 左 `-99` / 右 `-97`，
> 26.2 及更早左 `-100` / 右 `-99`。所以同一份配置五个版本都自洽，**版本差不需要任何容错**。

> 🔴 **0.4.0 改了名字**（0.4.1 修正了其中一处）：mod id `neko_voidwarehouse_search` → `neko_client`，产物 `neko-voidwarehouse-search` → `neko-client`，配置文件变成 `config/neko-client.json`（旧的 `neko-voidwarehouse-search.json` 不再读取），已绑的热键需要在配置界面里重绑一次。通道 id 没变，服务端不需要任何改动。
> ⚠️ **0.4.0 有个单人存档必崩的错误，0.4.1 已修**：0.4.0 把四条通道的 payload 类也一起挪进了 `neko.client`，而服务端 mod 里还有一份同名的旧包版本 —— 单人存档两端同进程，注册表里躺着的是**服务端那个类**的 codec，客户端却发自己类的实例，编码时 cast 失败（`Can't encode 'SearchHelloPayload[]', expected 'SearchHelloPayload[]'`，两个类同名不同包，报错看着一模一样）⇒ **一开仓库界面就断线**。0.4.1 把那四个类搬回 `neko.voidwarehouse.*` 并与服务端**逐字节对齐**；改了名字的只有客户端自己的逻辑（索引 / 配置 / 热键 / mixin）。

> 🔴 原版容器的点击协议里**没有修饰键**（`PICKUP / QUICK_MOVE / SWAP / CLONE / THROW / QUICK_CRAFT / PICKUP_ALL` 一个都带不了 Ctrl / Alt），所以这个手势只能在客户端识别，再走专用通道 `carpet_neko_addition:fill_request` 告诉服务端「点的是这一格、意图是填满」。**没装本 mod（或低于 0.2.0）的玩家，这个手势完全不存在**：点击就是原版的「取 1 个」，没有残迹也没有报错。

## 工作方式

```
打开仓库界面 ──search_hello──▶ 服务端确认是虚空仓库
             ◀─search_catalog─ 仓库物品 id 目录（≈30 KB）
输入 ─▶ 本地匹配（中文名 / 全拼 / 首字母 / 注册名，jpinyin 建索引）
     ──search_apply──▶ 服务端按 Item 身份过滤出页（空列表 = 恢复完整列表）
```

- 匹配在客户端做（只有客户端有中文语言文件），服务端只做集合求交；
- 过滤是**会话级**状态：关掉界面即消失，不写存档；页码回第一页；「可兑」虚拟条目同样参与搜索；
- 服务端限流：hello 100ms / apply 50ms，目录上限 4096 种，未知 id 静默忽略。

### 取满手势（0.2.0 起；0.4.3 起组合键可自定义；0.4.6 起严格按绑定鼠标键）

```
按住组合键 + 绑定的鼠标键点仓库格 ──fill_request{slotId}──▶ 服务端
                                                      ├─ 校验：菜单必须是虚空仓库（否则静默丢）
                                                      ├─ 校验：slotId 必须是内容格（导航行/背包格不认）
                                                      ├─ 校验：这一格要解析得出物品
                                                      ├─ 限流 50ms
                                                      └─ fill()：常规 = 纯散货填满背包 / 盒模式 = 满盒
◀──────────────────── 聊天提示「已取出 N 个 <物品>」─────────────────────
```

- **组合键**：`config/neko-client.json` 的 `keyFillCombo`，默认 `LEFT_CONTROL,LEFT_ALT,BUTTON_1`。判据（0.4.6 起只有这一条）：「**点的鼠标键码与绑定的鼠标键码逐位相等，且绑定的每个 Shift / Ctrl / Alt 在点击那一瞬间都按着**」（多按没绑的修饰键不算错，同 malilib 的 `allowExtraKeys`）；空串 = 手势关闭。绑定里**必须恰好一个鼠标键**：`BUTTON_1` = 左键、`BUTTON_2` = **右键**、`BUTTON_3` = 中键（26.3 也可写 `MOUSE_LEFT` / `MOUSE_RIGHT` / `MOUSE_MIDDLE`）。键盘那半边**只支持 Shift / Ctrl / Alt**：绑了别的键 → 组合键判「不可用」，进服日志会打出具体是哪个键 —— 不会静默不响应；
- 🔴 **0.4.6 起没有任何按钮号容错**：默认绑左键时，`Ctrl+Alt+右键` 一定不会取满（判据日志会写「未命中：点的是键码 -97，绑定的是 -99」）。想用右键就在配置界面把鼠标键改成右键，或把 `keyFillCombo` 写成 `LEFT_CONTROL,LEFT_ALT,BUTTON_2`；**改完退出重进一次世界**（或界面里改完立刻生效）。0.4.5 的「±2 容错」正是「绑左键却右键生效」的根因，已彻底删除；
- **只发 `slotId`**：物品是什么、能装多少，全由服务端从自己的数据和你的真实背包现算，客户端报的数字一概不作数；
- 客户端**只有真的把包发出去**才 cancel 掉原版点击；对端是老服务端（没这条通道）时原样放行，退回「取 1 个」；
- 「能装多少」= 三个上限取最小：背包放得下多少 / 仓库里有多少 / 盒模式下材料够做几盒。**一个都装不下时**会发一句提示，不会静默失败；
- 盒模式下潜影壳 / 箱子也能装盒，但材料账会先把「马上要装走的那批」刨掉（库存刚好只够一盒容量时一盒都不给，宽裕时照给满盒）。

### 「按了没反应」怎么自查（0.4.6 起）

进服后日志会打印 `取满组合键=…（判定：可用/不可用：原因）`。之后**每一次带修饰键的点击**都会留一行
`取满判据：按钮=… 键码=… 绑定鼠标键=… 组合键=… Shift/Ctrl/Alt=… ⇒ 命中（精确）/未命中：原因`；
判据日志与 `取满中止 / 取满降级 / 取满发包成功 / 取满链路` 等**链路结果日志各用一份限流预算**，
不会因为连点把关键结果挤掉。

| 日志里看到 | 结论 |
| --- | --- |
| 完全没有 `取满判据` 行 | 点击没进判据（开关关了 / 点击被别的模组先吞），先查 `fillGesture` |
| `组合键=不可用：…` | 绑定里混了字母键 / 没有鼠标键 / 有多个鼠标键，按提示改绑定 |
| `未命中：绑定的修饰键没按全` | 点击那一瞬间的修饰键掩码没读全（键盘侧问题） |
| `未命中：点的是键码 -97，绑定的是 -99` | **点错鼠标键了**：绑的是左键却点了右键。0.4.6 起这是设计行为；想用右键请把 `keyFillCombo` 的鼠标键改成 `BUTTON_2`（见上一段） |
| `取满中止：点击坐标 … 没落在 0..45 的内容格上` | 点在导航行 / 背包格 / 框外了 |
| `取满发包失败：… canSend=false` | 对端没装配套服务端 mod 或通道没注册 |
| `取满降级：目录未到` | 目录握手还没回来；请求仍会发出、这次点击退回原版「取 1 个」 |
| 判定行里的「组合键=…」和你以为的不一样 | 配置被改过 / 还没重进世界；手改 json 必须退出重进一次世界 |

## 安装

mod id `neko_client`，构件名 `neko-client`。五个 Minecraft 版本各一个 jar：

| 客户端版本 | jar | 构建管线 |
| --- | --- | --- |
| 26.3 / 26.2 / 26.1.2 / 26.1.1 | `neko-client-mc<ver>-0.4.6.jar` | fabric-loom（非 remap，Java 25） |
| 1.21.11 | `neko-client-mc1.21.11-0.4.6.jar` | fabric-loom-remap + officialMojangMappings（Java 21） |

| 位置 | 需要什么 |
| --- | --- |
| 客户端 | 本 mod（按版本选 jar）+ **malilib**（同版本，硬依赖）+ Fabric API（需搭配服务端 `carpet-Neko-Addition` 1.0.16+） |
| 服务端 | `carpet-Neko-Addition` 1.0.16+（对应版本 jar；本 mod 不是它的硬依赖，没有它时搜索框自动隐藏） |
| 纯原版客户端 | 什么都不用装，看不到任何变化 |

> 🔴 **0.3.0 起需要 malilib**（masa 系模组的公共库，装过 MiniHUD / Litematica / Tweakeroo 的玩家已经有）。用它换来的是：热键在**仓库界面打开着的时候也响应**（原版按键绑定只在没有界面时派发，而这两个键恰恰都是在界面里按的），以及一个和 MiniHUD 同款的配置界面。

## 使用

- 打开虚空仓库界面，点击界面上方的搜索框；
- 输入 `铁锭` / `tieding` / `td` / `iron_ingot` 均可命中；清空输入框 = 恢复完整列表；
- **按住组合键（默认 Ctrl + Alt）+ 绑定的鼠标键（默认左键）**点仓库里的物品格：取出到背包放不下为止（常规模式纯散货、潜影盒模式满盒）。想用右键就到「快捷键」页把 `取满组合键` 里的鼠标键改成右键，或把 `keyFillCombo` 写成 `LEFT_CONTROL,LEFT_ALT,BUTTON_2`；
- 🔴 聚焦搜索框时**所有按键都会被吞掉**（ESC = 退出搜索框，再按一次关界面）——否则数字键 `1-9` 会触发原版「把快捷栏整组存进仓库」的 SWAP 语义。组合键命中槽位时会自动让出焦点（原版点击被 cancel，它的「点框外失焦」不会执行，所以这里补上）。

### 开关与快捷键（0.2.0 起，0.3.0 换成 malilib，0.4.0 去掉默认键，0.4.3 取满组合键可改，0.4.6 严格按绑定键）

两个功能各自独立，互不影响；关掉一个不会影响另一个。

| 配置项 | 默认 | 关掉之后 |
| --- | --- | --- |
| `searchBox` | `true` | 界面里**不再创建**搜索框（不占地方、不吃按键、不发 `search_apply`），取满手势照常可用 |
| `fillGesture` | `true` | 取满手势退回原版「取 1 个」，搜索框照常可用（组合键还绑着也不响应） |

| 热键（配置界面里的名字） | 默认键 | 说明 |
| --- | --- | --- |
| 搜索框 / `searchBox` | **未绑定** | 切搜索框；**界面开着时立刻生效**（连带清空输入、撤掉服务端过滤） |
| 取满手势 / `fillGesture` | **未绑定** | 切取满手势；立刻生效，下一次点击就走新状态 |
| 取满组合键 / `fillCombo` | `LEFT_CONTROL,LEFT_ALT,BUTTON_1` | **不是开关，是手势本身**：按住它再点格子。清空 = 关掉手势。只支持「一个鼠标键 + Shift/Ctrl/Alt」，绑别的键会在进服日志报「不可用」。0.4.6 起**只认绑定的那个鼠标键**：`BUTTON_1` 左 / `BUTTON_2` 右 / `BUTTON_3` 中，未绑定的键一律不触发 |
| 打开配置界面 / `openGui` | **未绑定** | 打开本模组的 malilib 配置界面（开关、热键都在里面改） |

🔴 **为什么三条开关热键默认不给键**：`H` / `J` / `V` 这种单字母键在整合包里几乎必然与别的模组撞车，按下去先触发对方的概率远高于触发我们。空绑定在 malilib 里是合法状态（`allowEmpty=true`），代价只是「第一次要自己绑」。

🔴 **为什么 `fillCombo` 是唯一的例外（默认给了值）**：它的默认值**就是 0.4.2 及以前写死的那个组合键**。这里若也留空，老玩家升级后会看到「模组还在、开关还是开、可是按下去什么都不发生」—— 等于把一次「可配置化」做成了功能删除。

### 配置界面分了页（0.4.2 起，与 MiniHUD 同款）

界面顶部一排分类按钮，点一下换页；当前页的按钮置灰，跟 MiniHUD / Litematica 的配置界面长得一样（关掉再开还停在原页）。

| 分类 | 里面有什么 |
| --- | --- |
| **全部** | 四个条目全列一遍（想一次看全就停在这页） |
| **通用** | 两个功能开关：搜索框、取满手势 |
| **快捷键** | 纯热键条目：**取满组合键**、打开配置界面 |

🔴 **取满组合键为什么在「快捷键」页而不是「通用」页**：两个功能开关是 `ConfigBooleanHotkeyed`，**一行里同时有复选框和按键按钮** —— 它们的热键（= 切开关）本来就摆在功能自己那一行上。而 `fillCombo` 是个**纯热键**（没有布尔值），且它指的是「手势本身」而不是「开关」；放进「通用」页会和 `fillGesture` 挤在一起，看起来像两个开关。MiniHUD 也是这么分的：它的 `GENERIC_HOTKEYS` 页只放纯热键条目。

- **怎么绑**：进游戏后从 **Mod Menu**（装了的话）或任意 malilib 模组的配置界面右上角下拉框里选「Neko Client」，点热键按钮 → 按下新键（**鼠标键也能绑**：先点一下按钮进入「> … <」态，再按住修饰键点鼠标键；ESC 取消、Delete 清空）。改完点界面随便一处即可，`onSettingsChanged` / 关界面都会立刻存盘；
- **配置文件**：`config/neko-client.json`（首次启动自动生成，带 `_readme` 注释字段；热键存的是 malilib 的存储串，如 `H`、`LEFT_CONTROL,LEFT_ALT`、`LEFT_CONTROL,LEFT_ALT,BUTTON_1`，空串 = 未绑定）；
- **生效时机**：界面里改 / 按热键 → 立刻 + 当场写回；手改 json → **退出重进一次世界**（进服时重读）；
- 两个开关**都关**时客户端不发 `search_hello`，连那 ≈30 KB 的目录都不拉——只想安静用原版仓库的玩家可以这样彻底关掉；
- 🔴 **为什么必须是 malilib**：原版按键绑定只在 `Minecraft.screen == null` 时派发，而这俩键都是**在仓库界面里**按的，用原版绑定等于永远按不出来。malilib 的热键带 `Context`，这里取 `ANY`（游戏内 + 界面都响应）；同时设 `cancel=false`，所以搜索框聚焦时按热键仍然是正常打出字符（回调里也会主动让路）；
- ⚠️ 一个例外：**两个开关都关着时打开界面**，界面里根本不会创建搜索框；此时用热键把搜索框打开，需要**关掉界面再开一次**才会出现（框是在界面初始化时建的）。只要打开界面时有任意一个开关是开的，之后来回切都立刻生效。

### 通道撞名时会发生什么（0.4.1 的护栏）

Fabric 的 payload 注册表按通道 id 严格去重，「谁能编码这个 id」取决于**先注册那一方**塞进去的 codec。所以注册完之后客户端会回头核对一次归属：把这个 id 名下登记的 codec 取出来，跟自己的 `CODEC` **比引用**。

| 局面 | 日志 | 行为 |
| --- | --- | --- |
| 专用服务器（两边两个 JVM） | 无 | 自己注册成功，正常 |
| 单人存档（服务端 mod 先注册同一个类） | `WARN … 已被先注册，归属核对通过` | 正常 —— 单人里这条 WARN 是**常态**，不是错误 |
| 撞名的是**另一个类**（别的模组占了 id / 两端版本不配套） | `ERROR … 名下登记的不是本模组的 codec` | 该功能**自行关闭**，一个字节都不发；`WARN 通道自检未通过` |

🔴 为什么必须「发之前」拦：这类不匹配引发的异常发生在 **netty 线程**上（编码阶段 cast 失败），`try/catch` 根本碰不到，玩家只会看到断线。所以宁可搜索框不出现、取满手势退回原版「取 1 个」，也不许把客户端踢下线。
